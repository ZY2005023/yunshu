### 关于第 1 项：为什么以前没发现

占位密钥长 54 个字符，`security.py` 只校验「长度 ≥ 32」——**它能轻松通过校验**，
所以不会报错、不会告警，服务照常启动。这类问题只能显式比对拦下来。

现在的行为：

- `APP_ENV=production` 时，启动会检查密钥 / CORS / webhook / AI 密钥，
  任一不合规**直接拒绝启动**并打印原因。
- `APP_ENV=development`（默认）不拦截，方便本地调试。

## 三、部署前要准备的三样东西

### 1. 危机通知 webhook（唯一还缺的）

没有它，危机工单只是躺在后台列表里，**不会有任何老师收到通知** —— 这个模块等于没上线。

#### 怎么拿到地址（三选一）

**企业微信**（最省事，无安全限制）
1. 建一个群（值班老师 + 心理中心的人，**别拉全员**）
2. 群右上角 `···` → 群机器人 → 添加机器人 → 起名（如"云舒危机预警"）
3. 复制 Webhook 地址，形如 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxxxxxxx`

**钉钉**
1. 群设置 → 智能群助手 → 添加机器人 → 自定义
2. 安全设置选 **「自定义关键词」**（填"云舒"或"危机"），或填服务器 IP 段
3. ⚠️ **不要选「加签」** —— 加签需要对请求做 HMAC 签名，当前代码没实现，
   结果是收不到消息、且只在日志里留一行 warning（错误码 310000）
4. 复制 Webhook，形如 `https://oapi.dingtalk.com/robot/send?access_token=xxxxxxxx`

**飞书**

⚠️ 三个前提，缺一个就看不到入口（按踩坑概率排序）：

1. **必须用 PC 客户端**（电脑上装的飞书）。网页版和手机端**没有自定义机器人的入口** ——
   手机端只能添加"应用机器人"，那是另一种东西，拿不到 webhook。
2. **你得是群主或管理员**。群若设了"仅群主和管理员可添加机器人"，普通成员看不到入口。
3. **群类型不能是被限制的特殊群**（部分企业禁用了该功能）。

**最快的解法：自己新建一个群**（你就是群主，天然有权限，也绕开群类型限制），
加一两个测试同事即可。配好后再把机器人建到真正的值班群里。

路径（PC 客户端）：群聊 → 右上角设置 → 群机器人 → 添加机器人 → **自定义机器人**
→ 设头像/名称 → 添加 → 复制 Webhook，形如
`https://open.feishu.cn/open-apis/bot/v2/hook/xxxxxxxx`

➕ 如果机器人设置里有「签名校验」，**不要开** —— 开了对请求要求 HMAC 签名，
当前代码没实现，结果是收不到消息且只在日志里留一行 warning。

代码按地址里的域名自动选格式（飞书用 `msg_type`、企微/钉钉用 `msgtype`），**不用你额外配置**。

#### 填进去并验证

`apps/api/.env` 里加一行：

```
CRISIS_WEBHOOK_URL=https://你的地址
```

然后**必须跑一次验证**：

```bash
python scripts/test_webhook.py
```

它会打出平台识别结果、HTTP 状态和平台原始响应。**群里没看到消息就等于没配好** ——
别只看脚本说成功。

⚠️ 注意：**HTTP 200 不等于送达。** 实测企业微信地址填错时返回
`200 + {"errcode":93000}`，只看状态码会误判成成功。脚本会读 `errcode` 并给出具体原因。

如果请求根本发不出去，多半是服务器不能访问外网（校园内网常见），需要配代理。

### 2. JWT 密钥（已生成）

已写入 `apps/api/.env`，64 位随机值。**注意：换密钥会让所有已登录用户掉线，需要重新登录。**
如需重新生成：

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

### 3. HTTPS 证书

- 正式环境：签发证书，放到 `deploy/certs/fullchain.pem` 和 `deploy/certs/privkey.pem`
- 内网试用：可以自签（浏览器会告警，仅内网可接受）

```bash
openssl req -x509 -nodes -newkey rsa:2048 -days 365 \
  -keyout deploy/certs/privkey.pem -out deploy/certs/fullchain.pem -subj "/CN=你的域名"
```

## 四、部署步骤

### 方式 A：容器部署（推荐）

```bash
# 1. 构建前端（api 容器把 dist 挂成 /app/static，不构建就只有接口没页面）
cd apps/web && npm run build && cd ../..

# 2. 起库
cd deploy
docker compose up -d mysql

# 3. 迁移（⚠️ 建表只交给 Alembic，别挂 initdb.d，否则版本记录对不上）
docker compose run --rm api alembic upgrade head

# 4. 起服务
docker compose up -d api nginx

# 5. 自检
python scripts/predeploy_check.py
```

### 方式 B：直接跑后端（后端自己托管前端产物）

后端会把 `apps/api/static/` 挂成静态目录，同源部署因此**不需要 CORS**。

```bash
cd apps/web && npm run build
cp -r dist ../api/static        # Windows: xcopy /E /I dist ..\api\static
cd ../api
set APP_ENV=production
uvicorn app.main:app --host 0.0.0.0 --port 1236
```

前端由 nginx 做 TLS 终止后反代到 1236（配置见 `deploy/nginx.conf`）。

### 切到生产模式

把 `apps/api/.env` 里的 `APP_ENV` 改成 `production`。**改完如果启动被拒，说明还有配置没到位
——这正是闸门的目的，别把它改回去绕过。**

## 五、上线后必须盯的事

| 观察项 | 怎么看 | 多久 |
|---|---|---|
| SSE 是否真在流式 | 对话页看是否逐字输出，而不是一次性吐出 | 上线当天 |
| 危机通知是否真收到 | 触发一次测试事件，确认群里收到 | 上线当天 |
| 备份是否在做 | `python scripts/backup_db.py --list` | 每周 |
| 迁移是否有漂移 | `python scripts/predeploy_check.py` | 每次发布前 |

**单 worker 的并发天花板**：SSE 会占住 worker，`--workers 1` 下并发在途请求上限是 1。
人一多就会排队。扩容前必须先把 token 黑名单和对话记忆外置到 Redis，否则登出/改密不生效、
AI 会失忆（详见 `apps/api/Dockerfile` 里的注释）。

## 七、已知限制（不是 bug，但要有数）

1. **单 worker 并发上限**：见第五节。
2. **进程内对话记忆**：后端一重启，AI 就忘了之前聊过什么（`_store` 是模块级字典，从不落库、
   重启不重载）。多 worker 部署同样会出问题。
3. **前端每次进对话页都会新建空会话**：历史要点左侧列表才加载回来。**数据没丢**，
   只是不会自动恢复。
4. **误报**：关键词规则必然有误报（实测「推荐几本关于焦虑的书」被判成 1 级）。
   降噪策略（1 级不推送、误报原因结构化、合并窗口）需要和心理中心一起定，
   不建议单方面拍板。
5. **接口文档匿名可见**：已在 nginx 里限制为内网网段，按你们实际网段调整。
