### 1. 配置 `.env`（不做这一步，服务起不来或仍用默认弱口令）

| 变量 | 说明 |
|---|---|
| `DB_PASSWORD` | 数据库口令（原先是明文 `123456`） |
| `AI_API_KEY` | 见下方第 2 条，**必须换新的** |
| `JWT_SECRET` | **必须换新**，长度 ≥ 32 字符的随机串 |

生成强随机密钥（任选一条命令）：

```bash
# Linux / macOS / Git Bash
openssl rand -base64 48
```

```powershell
# Windows PowerShell
[Convert]::ToBase64String((1..48 | ForEach-Object { Get-Random -Max 256 }))
```

> `application.yml` 里写的是 `${JWT_SECRET:...}` 形式，`.env` 通过
> `spring.config.import: optional:file:.env[properties]` 自动加载。
> `.env` 已被 `.gitignore` 忽略，不会入库。

### 2. 作废并重签 DeepSeek Key（必须做，属于已泄漏凭证）

原来的 Key（`sk-d791…`）曾以明文写在 `application.yml` 里。**代码里的明文已清除，但这个 Key 本身仍应视为已泄漏**：

1. 登录 DeepSeek 控制台 → 删除旧 Key → 新建一个；
2. 新 Key 只写进 `backend/.env`，不要写回 `application.yml`。

### 3. 执行建表脚本（危机干预依赖它）


### ⚠️ 有意的偏差：`/files/**` 保持匿名可访问

方案原文写的是"`/files/**` 改需登录"，实施时**没有照做**，原因：

上传的图片（文章封面、头像）是靠 HTML `<img src>` 直接引用的，浏览器发 `<img>` 请求时
**不会带 `Authorization` 头** —— 一旦改成"需登录"，所有图片会集体 404。

改为等价的补偿措施：
- 文件名从原文件名改为 **UUID**，不可预测、不可枚举；
- 上传即做扩展名白名单 + 魔数校验，`html/svg/js/jsp` 之类一律拒收；
- 严格鉴权（签名 URL）留到 **P1** 处理。
