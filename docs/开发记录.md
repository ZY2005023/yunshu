## 一、快速开始

### 1. 准备环境

```bash
make setup          # 建 .venv 并装后端依赖
cd apps/web && npm install   # 前端依赖（若 node_modules 已随仓库搬来可跳过）
```

### 2. 配置环境变量

```bash
cp apps/api/.env.example apps/api/.env
```

最少要填两项：

| 变量 | 说明 |
|---|---|
| `DB_PASSWORD` | 数据库口令 |
| `JWT_SECRET` | **生产必改**，≥ 32 位，不足会直接抛异常 |
| `AI_API_KEY` | DeepSeek Key（不填则 AI 相关功能降级，其余照常） |

环境变量模板见 `apps/api/.env.example`，逐项都有注释。
注意 AI 的 Key 变量名是 `AI_API_KEY`。

### 3. 起数据库并建表

```bash
cd deploy && docker compose up -d mysql
make migrate        # 或：cd apps/api && .venv/Scripts/python.exe -m alembic upgrade head
```

> ⚠️ 建表**只交给 Alembic**，不要把 `database/V1__init_schema.sql` 挂进
> `docker-entrypoint-initdb.d` —— 两套机制并用会导致 Alembic 没有版本记录，后续迁移对不上。

### 4. 启动

双击 **`启动云舒.cmd`**，或：

```bash
make api     # 后端 http://localhost:1236，接口文档 http://localhost:1236/docs
make web     # 前端 http://localhost:5173
```

停止：双击 **`停止云舒.cmd`**。

### 5. 生产形态

FastAPI 同时托管前端产物（`apps/web/dist` → `/app/static`），前后端同源，
免配 CORS、免配 SSE 的 `proxy_buffering`。

```bash
make build                      # 产出 apps/web/dist
cd deploy && docker compose up -d
```

## 五、接口契约与兼容约定

这些是前后端之间的硬约束 —— **看起来像 bug 但必须保留**，改动任何一条前端都会坏。
完整清单见 `docs/云舒-接口契约清单.md`。

1. **`Result.code` 是字符串**（`"200"` / `"A0301"`）—— 返回整数会让全站判定失效
2. **`A0230` 被 TOKEN_INVALID / EXPIRED / BLOCKED 三者共用** —— 不要拆成三个码
3. **SSE `done` 事件的 data 是裸 `{}`** —— 不是 Result 包装
4. **SSE 每段延时 50ms** —— 少了不报错，但前端被碎片冲垮
5. **业务异常默认码是 `6000` 不是 `-1`**（`errors.ERROR` 定义了但从代码里从未使用）
6. **权限不足（管理接口）返回 HTTP 400**，不是 403
7. **`roleType`** 在 JWT claim 里是整数，在登录响应里是字符串
8. **JWT 的 `exp`/`iat` 是秒级**，配置里的毫秒要 `/1000`
9. **`/session/{id}/emotion` 是单数、`/sessions/{id}/messages` 是复数** —— 路径刻意如此，别"顺手统一"
10. **`helplines` 是纯字符串数组**，不是对象数组
11. **文章详情访问即阅读数 +1**
12. **危机列表 size 上限 50**，咨询列表也是 50，其余 100
13. **四舍五入统一用 `round_half_up()`** —— Python 内建 `round()` 是银行家舍入（`round(2.5) == 2`），统计/看板用了会出现 0.1 级偏差
14. **`Form()` 必须写 alias** —— 否则前端传的 `businessType` 匹配不到
15. **注册强制 `userType = 1`** —— 堵住匿名注册接口的提权漏洞

## 七、前端设计系统

改版目标：让 14 个页面看起来像同一个产品，而不是各自拼出来的。

### 唯一要记住的约定

**颜色、圆角、阴影、间距一律走 CSS 变量**（`--nd-*`），页面里写死色值会在换主题时留下漏网之鱼。
变量定义在 `apps/web/src/style.css`，全项目 452 处引用、覆盖 25 个文件。

### ⚠️ main.js 的引入顺序不能调换

```js
import 'element-plus/dist/index.css' // 必须先
import './style.css'                 // 必须后
```

反过来写，对 Element Plus 的主题覆盖会**静默失效**（同权重选择器后者胜）。
验证命令见本节末尾。

### 品牌色

| 用途 | 变量 | 值 |
|---|---|---|
| 主色 | `--nd-primary-500` | `#2f9c8b`（青绿） |
| 辅助暖色 | `--nd-accent-500` | `#efab3c` |
| 语义色 | `--nd-success` / `--nd-warning` / `--nd-danger` | 见 style.css |
| 页面底 / 卡片 | `--nd-bg` / `--nd-surface` | `#f4f8f7` / `#ffffff` |

顶栏高度 `--nd-navbar-h` 被对话页、日记页用来算「视口高度减去顶栏」——
改它会连带影响这两个页面的高度计算。

### 覆盖范围

| 区域 | 改了什么 |
|---|---|
| 全局 | 设计令牌 + Element Plus 主题覆盖 + 通用类（`nd-card` / `nd-empty` / `nd-badge` / `nd-container` …） |
| 认证 | 左栏改为品牌价值展示（含求助热线兜底）；登录补记住我 / 忘记密码 / 协议提示；注册补密码强度与协议强制勾选 |
| 用户端布局 | 吸顶毛玻璃导航、移动端抽屉菜单、全局页脚（含免责声明）；`meta.fullHeight` 的页面自动隐藏页脚 |
| 首页 | 单屏 hero → 完整落地页（Hero / 功能 / 流程 / 能力 / CTA） |
| 管理端布局 | 侧边栏按业务分组 + 跟随路由自动高亮；顶栏面包屑 + 真实管理员信息 |
| 业务页 | 14 个页面统一配色与响应式；对话页、日记页的双栏在小屏改单栏 |

### 顺带修掉的真实问题

1. **侧边栏 `default-active="2"` 是硬编码** —— 菜单高亮永远停在第 2 项，看不出当前在哪
2. **顶栏用户名硬编码 `admin`**，头像用外链占位图（`cube.elemecdn.com`），断网即裂图
3. **知识库页标题误写成「情绪日志」**（复制粘贴遗留）
4. **`Plain` 大写属性**（Element Plus 的 prop 是 `plain`）、**`font-size: 12` 缺单位**等无效代码
5. **多个页面固定 `width: 1200px`** —— 小屏横向溢出
6. **`userType === 2` 严格比较** —— localStorage 里若存成字符串 `"2"`，管理员会被误判成普通用户
7. **管理端登出没带 refreshToken** —— 后端无法吊销（用户端带了）

## 八、把接口导入 Apifox

### 为什么不能直接导入 `/openapi.json`

FastAPI 自带的 `/openapi.json` 能导入，但导入后**几乎不可用**，它缺四样东西：

| 缺失 | 后果 |
|---|---|
| 没有 `servers` | Apifox 要你手填服务地址 |
| **没有认证声明** | 项目用的是自定义依赖（见 `app/deps.py`），不是 FastAPI 的 `HTTPBearer`，所以 schema 里没有 `securitySchemes` → **需鉴权的接口全都要手工加 `Authorization` 头** |
| SSE 被写成 `application/json` | 流式接口的 6 类事件一个字都没描述 |

脚本会把上面四项都补齐，并跑一遍**只读接口**把真实响应体填成 `example`（写操作不采，避免改数据）。

### 在 Apifox 里导入

1. 主界面 → **导入项目**（或已有项目的「项目设置 → 导入数据」）
2. 选 **OpenAPI/Swagger**，把 `docs/openapi-apifox.json` 拖进去
3. 解析成功后会出现 **「选择接口的维护方式」**，**必须选「以可视化界面维护接口」**。
   > ⚠️ 若选了「以 OpenAPI 文件维护接口（spec 模式）」，**不会显示预览和任何导入选项** ——
   > 下面的开关就都找不到了。
4. 之后进入 **「预览 & 勾选」** 页（左侧是接口树，右侧是导入选项），
   右侧是**一串平铺的开关**（2.8.49 没有分组标题），按下面设置：

   | 开关（界面原文） | 设为 | 作用 |
   |---|---|---|
   | 为每个接口自动生成一个调试用例 | **开** | 每个接口附一个「成功」用例，导入后可直接点运行 |
   | **将 OpenAPI/Swagger 里的 Servers 导入为环境** | **开** | 建出 `本地直连(1236)` / `本地代理(5173)` 两个环境，省得手填地址 |
   | **导入 Security Scheme** | **开** | **最关键** —— Bearer 认证定义靠它导进来 |
   | └ 将目录 "Root" 的 Auth 设置为 OpenAPI 的全局 Security (JWT Bearer) | **开** | Root 拿到全局认证，下面"未设置 Security"的接口继承它 |
   | 当导入的接口**有**设置 Security 时 | 对应的鉴权组件 | 登录/注册/刷新/登出 4 个走这条（它们本就无需令牌） |
   | 当导入的接口**未**设置 Security 时 | **继承父级** | 其余 35 个走这条 → 继承 Root 的 JWT Bearer ✓ |

   > ⚠️ 那个 **Servers 开关默认是关的**，最容易漏。
   > 不打开的话，导入后每个请求都要自己填服务地址。

5. 导入后只需配**一次**认证：登录接口 → 后置操作 → 提取变量 `data.token`，
   再把它绑到全局 Bearer 认证（或直接在「环境 → 全局参数」里加 `Authorization: Bearer {{token}}`）

> 也可以直接用 **URL 导入**（填 `http://127.0.0.1:1236/openapi.json`），
> 但那样拿到的就是上面说的"四缺"版本，所有接口都得手工配鉴权头。
> 想定时同步的话，用 URL 导入 + 自动导入更省事，代价是每次都要手工维护认证。

### 漏勾了怎么办

不用重新导入，项目设置里可以后补：

- **环境** → 项目设置 → 环境管理，手动加 `http://127.0.0.1:1236`
- **认证** → 项目设置 → Auth（鉴权），加一条 Bearer Token
- **用例** → 在目录上右键，批量生成接口用例

### 两个容易踩的点

- **业务失败也是 HTTP 200**。判成功要看 body 里的 `code == "200"`，
  不能只看状态码 —— 参数校验失败返回的是 `HTTP 200` + `code:"400"`。
- **SSE 在 Apifox 的「返回响应」面板里看不到增量内容**。它是 `text/event-stream`，
  不是普通 JSON。调试用 `curl -N` 或 Apifox 的运行控制台。

> `docs/openapi-apifox.json` 是**生成物**，改接口后要重跑 `make api-docs`。
> 别手工编辑它 —— 下次导出会被覆盖。生成逻辑在 `scripts/export_openapi.py`。

### 7. 看板「平均情绪」的口径（附一个会误导人的显示 bug）

**先回答一个常被问到的问题：那条线是不是「全站所有用户的平均」？**

是。`analytics.overview` 里的查询**没有任何 user_id 过滤**：

```python
diaries_week = select(EmotionDiary).where(EmotionDiary.created_at >= week_ago)
```

准确口径是：**近 7 天内，所有用户当天日记的 `mood_score` 算术平均**
（不是「每个用户先算日均、再对用户求平均」）。
另外两条要知道的细节：

- 分组用的是 **`created_at`（写入时间）而不是 `diary_date`（心情所属日期）** ——
  今天补写昨天的日记，会算进今天（既有的统计口径）。
- 返回的 `avgMoodScore`（系统概览里那个）是近 7 天**所有日记**的均值，
  与按天的 `trendData` 不是同一个聚合层次。

**发现的显示 bug：无记录的天被画成「情绪 0 分」**

后端对「当天没有日记」返回 `avgMoodScore = 0`。但 `mood_score` 的合法范围是
**1~10，0 根本不是有效评分**（`DiaryIn.mood_score` 是 `ge=1, le=10`）。
前端直接 `map(item => item.avgMoodScore)` 就把它画成了折线上真实的 0 ——
看起来像「全体用户情绪跌到谷底」，实际只是「那天没人记录」。

心理健康看板上这种误读代价很高，所以做了两处修正：

| 改动 | 说明 |
|---|---|
| 评分序列无记录时置 `null` | echarts 会**断开折线**而不是画到 0。逻辑抽到 `utils/analyticsChart.js` 并补了 10 个单测（含「有记录且分数恰为 0 时保留 0」的边界） |
| 记录数量序列保留 0 | 那条线本来就该是 0 —— 那天确实记录了 0 条 |
| 卡片头部显示「近 7 天中有 N 天有记录」 | 数据稀疏时（例如 7 天只有 3 天有数据），单看一条折线容易过度解读 |

顺带清掉一处重复：卡片头部与 echarts 自己的 `title` 都写着「情绪趋势分析」，
且 echarts 的两行标题（`text` + `subtext`）会和 `legend` 重叠。
**结论：图表标题只放一处**（放卡片头部），别在 echarts 里再写一遍。

### 新功能：知识库文档导入（txt / md / docx / pdf）

管理端「知识文章 → 新增/编辑」的编辑器上方新增「从文档导入」按钮：
**上传 → 解析 → 预填编辑器 → 人工校对后保存**。

**刻意不直接入库**：① 文档解析难免有格式噪音，直接入库会污染 RAG 检索质量；
② 心理类内容上线前本来就该人审一遍。所以后端只解析、不落库（见
`services/doc_import.py`），保存仍走既有的文章接口。

| 能力 | 说明 |
|---|---|
| 格式 | txt / md / docx / pdf；大小沿用 `FILE_MAX_SIZE`（默认 5MB） |
| 编码 | UTF-8 优先，**GBK 兜底**（Windows 记事本中文 txt 的高频真实现状），兜底时给警告 |
| Markdown | 标题/加粗/列表/代码块/引用 → HTML（与前端 MarkdownRenderer 同口径的先转义后转换，最后过 sanitize 白名单） |
| Word | 段落 + **表格**（按行转文本，学校材料表格很多）；加密/损坏文档给可读报错 |
| PDF | 逐页提取文字层；**扫描件（整页图片）识别为不可用**并明确提示需要 OCR（暂不支持），不是丢一个空编辑器 |
| 预填 | 标题取文件名（`睡眠指南_v2.docx` → 「睡眠指南 v2」，不覆盖已填标题）；字数超 5000 上限时给出醒目提醒 |
| 接口 | `POST /api/knowledge/admin/import-document`（👑，只解析不落库） |
| 测试 | 后端 +12：四种格式 / GBK / 表格 / 扫描件 / 类型与大小拒绝 / 越权 / **不落库断言** |

新增依赖：`python-docx`、`pypdf`（已同步进 `pyproject.toml` 与 `Dockerfile`；
解析库**延迟导入** —— 不用导入功能的环境不为它们付启动成本）。

浏览器实测（Playwright）已通过：导入含表格的 docx → 标题/正文预填、表格转文本、
警告提示显示、0 页面异常。
