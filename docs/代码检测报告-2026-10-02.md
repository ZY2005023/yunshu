## 一、已修复（3 处）

### 1. `copy-promises.spec.js` 路径解析错误 —— 测试基础设施 bug

**现象**：`make webtest` 失败 1 项，是**长期潜伏**的用例。

```
Error: ENOENT: ...\apps\web\api\app\services\crisis.py
```

**根因**：`here` = `src/__tests__/`，`path.resolve(here, '../../api/...')` 解析到
`apps/web/api/...`（多了一层 `web`），应为 `../../../api/...`（退三级）。

**为什么以前不报**：该用例被 `if (CRISIS.includes('按风险等级排序'))` 包着。
`crisis.vue` 这轮改版新增了这句文案，才第一次真正去读那个文件。

**已验证文案本身是对的**：后端 `services/crisis.py:171` 确实
`.order_by(CrisisEvent.level.desc(), ...)`，所以这是测试自身的 bug，不是功能 bug。

**修法**：补三级 `../` 并加注释说明层级。修复后 142 项全过。

### 2-3. 两处全角空格（U+3000）导致 ESLint 报错

`no-irregular-whitespace` × 3：`emotionDiary.vue:520`、`scale.vue:68`（两处）。
用 `cat -A` 定位到 `M-oM-<M-^I`（即 U+3000），已替换为普通空格。

**注意**：这个字符在 crisis.py 里有**语义** —— 显式用 `_ASCII_WS` 避免 `\s`
吃掉全角空格。**但那是后端正则，前端文案里的全角空格纯属笔误**，两回事。

## 二、确认是真 bug（4 处，均未修 —— 需你确认后我再动）

### A. `consultation.vue` 消息时间恒为空

- `consultation.vue:367/408/433` push 消息时写 `createAt`
- `consultation.vue:159` 模板渲染 `msg.createdAt`
- 对照 `consultations.vue:60` 用的是 `message.createdAt`（正确）

**影响**：本次会话中**新发**消息的时间列不显示。历史消息（从后端加载的）
正常，因为后端 `MessageRow` 出参是 `createdAt`。

**根因**：改名「宁渡课堂 → 云舒」那类手工同步遗漏，与已知的
`crisis.vue` 表格列标签错位、`profile.vue` 漏改 `Number()` 同源。

### B. `emotional.vue` 分页参数名错 —— 永远回第 1 页

- `emotional.vue` 唯一用 `current`，其余 8 个页面全用 `currentPage`
- 后端 `ApiIn` 基类：`alias_generator=to_camel` + `populate_by_name=True` +
  **`extra="ignore"`**
- 所以后端接受 `currentPage` / `current_page`，**但不认 `current`** →
  被 `extra="ignore"` **静默丢弃**

**为什么难发现**：不报错、不抛异常，永远返回第 1 页。翻页看着像"没反应"。

**附带**：`emotional.vue:262` `onMounted(() => handleSearch())` 不传参，
`handleSearch(formData)` 收到 `undefined`，筛选条件同样静默丢失。

### C. `consultations.vue` 消息列表渲染错误

两端调**完全相同**的 URL（`frontend.js` 与 `admin.js` 各封装一份）：

```
GET /api/psychological-chat/sessions/{id}/messages
```

后端返回 `MessagesOut = {sessionId, messages: [...]}`（`schemas.py:385`）。
`consultation.vue:568` 正确取 `res.messages`；
**`consultations.vue:96` 直接 `sessionMessages.value = res`**，
模板 `v-for="message in sessionMessages"` 于是**遍历对象**，
拿到 `sessionId` 和 `messages` 两个键，渲染成两条空消息项。

### D. `ArticleDialog.vue` 表单校验失败仍会提交

```js

    if (valid) { loading.value = true }   // ← 没有 else / return
```

### E. `users.vue` "不能禁用自己"的前端保护失效

`users.vue:131` 用了 `useUserStore()`，但管理端（`BackendLayout` / `Navbar`）

于是管理员进 `/back/users` 时 `myId` 为 `undefined`，`isMe()` 恒 false
（`users.vue:176` 有 `!= null` 保护，所以不报错，只是**静默失效**）。

后端仍会拦，但前端"我"标记与禁用按钮保护都不生效，提示误导。

## 三、安全与合规风险（3 处）

### 1. ⚠️ CORS 组合危险：`allow_origins=["*"]` + `allow_credentials=True`

`main.py:47-53`。已查 Starlette 源码确认行为：
`preflight_explicit_allow_origin = not allow_all_origins or allow_credentials`
→ 因 `allow_credentials=True`，**预检时回显请求的 Origin 而非 `*`，
同时发 `Access-Control-Allow-Credentials: true`**。

即**任意站点**都能带凭据读本项目响应。当前项目用 Bearer token
（存 localStorage，不自动携带），实际可利用性有限，但这是**明确的配置错误**。
注释自己写着「拆分部署请收紧成白名单」，却没做。
同源部署下这段 CORS 根本用不到，建议直接删或改成白名单。

### 2. 危机工单**无主动触达**（`.env` 未配 webhook）

`.env` 与 `.env.example` 均无 `CRISIS_WEBHOOK_URL`。
`notifier.py:96` 读到空就只写日志。README 自己写明
「**不配置等于没有主动触达**」—— 目前只有后台列表和角标。
**这是心理健康产品，上线前必须配。**

### 3. 零速率限制

登录可无限爆破；AI 接口可被刷（`userMessage` 限 2000 字但不防高频）。
README 已列在「仍未实现 D」。
