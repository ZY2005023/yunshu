## 一、这一轮解决了什么

上一轮 P1 卡在一个硬点上：本机 Maven 仓库（`env/repository`）是**离线快照**，
缺少 Flyway、springdoc、actuator、MapStruct、surefire 等依赖，
导致**这个项目连 `mvn test` 都跑不起来**。

经确认后联网补齐了这批依赖。**所有下载都落在项目目录内**：

| 生态 | 落点 | 是否在项目内 |
|---|---|---|
| Maven（后端） | `mental-health/env/repository` | ✅ 是 |
| npm（前端） | `mental-health/frontend/node_modules` | ✅ 是 |
| Docker 基础镜像 | Docker Desktop 镜像库 | ⛔ 否（本轮**未**拉取） |

三点值得说明：

1. **`C:\Users\23540\.m2` 至今不存在** —— 这几轮构建一个字节都没写进系统盘。
   隔离靠的是每次构建显式传的 `-Dmaven.repo.local=<项目>/env/repository`。
   ⚠️ 直接敲 `mvn`（不带该参数）会创建并写入 `~/.m2/repository`，破坏隔离。
2. **仓库 ID 保持一致**：下载用的是 `env/settings.xml`（mirror id = `aliyunmaven`），
   与快照中已有构件的 `_remote.repositories` 记录一致，
   所以**后续离线构建依然可用**（已实测，见验证表）。
3. 前端新增 `frontend/.npmrc` 固定 `registry=https://registry.npmmirror.com`，
   与既有 `package-lock.json` 中 222 条 `resolved` 地址保持一致，避免 lock 里混入两种源。

## 二、一个差点造成数据灾难的发现

把 `mental_health_assistant_full.sql` 转成 Flyway 迁移脚本时发现：
**这份脚本里有 9 条 `DROP TABLE IF EXISTS`**。

它是 Navicat 导出的"先删后建"件。如果原样当作迁移脚本，在已有数据的库上执行
就是**全表清空**。转换时已作三处必要修改（V1 文件头部有注明）：

| 原写法 | 改为 | 原因 |
|---|---|---|
| `DROP TABLE IF EXISTS xxx` ×9 | **整行删除** | 否则在存量库上执行 = 清库 |
| `CREATE TABLE xxx` | `CREATE TABLE IF NOT EXISTS` | 幂等，可安全重跑 |
| `INSERT INTO` | `INSERT IGNORE INTO` | 种子数据重复时跳过而非报错 |

### 3. MapStruct 取代手写转换器

删除 `service/convert/UserConvert.java`，改为 `UserConvertMapper` 接口
（`@Mapper(componentModel = "spring")`），调用方 `UserService` / `UserController` 改为注入使用。

两个关键设计：

- **`unmappedTargetPolicy = ReportingPolicy.ERROR`**。默认的 `WARN` 会让
  "实体加了字段却忘了映射"静默通过，等前端发现某字段永远是 `null` 才回头查。
  设为 `ERROR` 后，加字段不更新映射直接编译失败。
- **`lombok-mapstruct-binding` 显式声明**。这是最经典的陷阱：不配它，
  MapStruct 会先于 Lombok 运行、读不到 Lombok 生成的 getter，
  **静默生成空实现**（编译通过、运行全是 null）。
  已核对生成的 `UserConvertMapperImpl`，确实调用了 `getUserTypeDisplayName()` 等
  Lombok 生成的 getter，说明绑定生效。

### 4. Flyway：脚本已就位，但默认**关闭**

新增：

```
backend/src/main/resources/db/migration/
├── V1__init_schema.sql    # 现有 9 张表 + 种子数据（已剥离 DROP TABLE）
└── V2__crisis_event.sql   # P0 的危机事件表
```

**⚠️ 默认 `FLYWAY_ENABLED=false`，这是刻意的，不是漏配。** 原因有实测支撑：

> 加完 `flyway-core` 依赖后第一次跑测试，日志里出现
> `flywayInitializer ... Access denied for user 'root'@'localhost'` ——
> 说明**只要 flyway-core 进入 classpath，Spring Boot 就会自动装配 Flyway
> 并在每次启动时连库执行迁移**。

而本库是"先有数据、后引入迁移工具"的存量库，没有 `flyway_schema_history` 表，
直接开启会走 baseline 逻辑。**参数配错面对的是真实心理数据，没有重来的机会。**

启用步骤（建议先备份库，再到开发库演练）：

```bash
# 1) 确认 baseline 参数与库状态匹配（application.yml 已设默认值）
#    baseline-on-migrate = true   非空库自动建立基线
#    baseline-version    = 1      已有库跳过 V1，只应用 V2 起的变更
#    clean-disabled      = true   禁止 flyway clean（防误删整库）
# 2) 打开开关
FLYWAY_ENABLED=true
```

启用后行为对照：

| 数据库状态 | Flyway 行为 |
|---|---|
| 已有数据、无 history 表 | 基线到 v1（V1 不执行）→ 应用 V2 |
| 全新空库 | 应用 V1 → V2 |

顺带一个副产品：`docker-compose.yml` 的 MySQL 初始化挂载已从"两个游离 SQL 文件"
改为**直接挂载 `db/migration` 目录**。这样"容器首次建库"和"后续迁移"用同一份 DDL，
不会出现两套建表语句各自演化。README 里的 `mental_health_assistant_full.sql` 与
`数据库变更-2026-09-30.sql` 从此降级为历史参考件，**不要再基于它们做变更**。

### 5. actuator（健康检查）与 springdoc（接口文档）

**actuator**：只暴露 `health` 与 `info`。`env` / `beans` / `heapdump` / `threaddump`
在未鉴权时会泄露配置项与内存内容，一律不开。
`show-details=when-authorized` —— 匿名访问 `/actuator/health` 只拿到 UP/DOWN，
已认证用户才看得到 db、磁盘等明细。`/actuator/health` 已加入匿名白名单
（负载均衡与容器编排需要探测，且不透露任何组件信息）。

**springdoc**：默认 `SPRINGDOC_ENABLED=false`。
⚠️ 开启后接口清单对匿名用户可见（白名单里那两条 `swagger-ui` 条目此时才会生效），
**生产环境请保持关闭**。本地要看文档就设 `SPRINGDOC_ENABLED=true`。

### 6. 前端 lint 与单元测试工具链

新增 `eslint.config.js`（flat config）/ `.prettierrc` / `.prettierignore` / `vitest.config.js`，
以及两个测试文件（38 个用例）。package.json 新增脚本：

```bash
npm run lint          # ESLint
npm run lint:fix      # ESLint 自动修
npm run format        # Prettier 格式化
npm run format:check  # 只检查不改
npm test              # Vitest 单测
npm run test:watch    # 监听模式
```

**规则取舍**：存量代码的规则设为 `warn` 而非 `error`。一上来全 `error` 会红成一片、
没人会真去看；先把护栏立起来、逐轮收紧。护栏类规则（`no-debugger`、`no-var`、`eqeqeq`）
保持 `error`。

**修复的问题**：2 个 error（`router/index.js` 的 `==`、`sanitize.js` 中被误报的控制字符正则）
+ 3 处无用导入（`Navbar.vue` / `home.vue` / `frontendKnowledge.vue`）。
`router/index.js` 那处改成了 `Number(userInfo.userType) === 2` —— 因为 `userInfo`
来自 localStorage 反序列化，历史上出现过 `userType` 被存成字符串的情况，
直接写 `=== 2` 反而会让管理员跳转失效。

**余下 28 条 warning 未处理**，主要是两类，都保留了：

- `vue/attribute-hyphenation`（约 12 条）：如 `:maxCharCount` 应写 `:max-char-count`。
  Vue 对 camelCase 属性是兼容的，改动只是规范收益，但会动到大量模板，风险收益比不划算。
- `vue/no-v-html`（5 条）：**这是有意保留的安全网**。这 5 处已全部接 `sanitizeHtml()`，
  但留着这条规则，将来有人新写未清洗的 `v-html` 时会被提示。

**建议**：`npm run format` 首次执行会产生较大 diff（存量代码未按当前 Prettier 规则排过版），
**单独提交一次**、不要和功能改动混在一起。

## 六、Docker 怎么用

```bash
cd ai-api-test/mental-health

# 1) 准备密钥
cp docker.env.example .env
# 编辑 .env：填 DB_PASSWORD / JWT_SECRET（≥32 位）/ AI_API_KEY

# 2) 起服务（首次构建需联网拉基础镜像，本机尚未拉取）
docker compose up -d --build

# 3) 打开 http://localhost:8080
```

常用命令：

```bash
docker compose logs -f backend     # 看后端日志
docker compose ps                  # 看服务状态
docker compose down                # 停止（保留数据）
docker compose down -v             # 停止并清空数据库与上传文件（慎用）
```

⚠️ **首次构建必须联网**（拉 mysql / maven / node / nginx 镜像）。
本机 `env/` 下的离线 Maven 仓库只服务于"宿主机直接构建"，容器内用不到。
本轮按约定**没有拉取任何 Docker 镜像**。
