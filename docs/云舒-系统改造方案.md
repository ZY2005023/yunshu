> **审查方式**：纯静态只读审查。**没有启动后端、没有装依赖、没有连数据库、没有跑前端**——只读源码 + 配置 + SQL + 文档，逐条给出 `文件:行号` 证据。
> **审查日期**：2026-09-30
> **被审对象**：`ai-api-test/mental-health/`（后端 62 个 Java 文件 / 前端 11 视图 + 11 组件 / 1 份建表 SQL）

## 一、结论速览

**先回答你最关心的问题：这个项目"完成"了吗？**

分三种口径回答：

| 口径 | 结论 |
|---|---|
| **功能能不能跑通？** | **能。** 注册登录、AI 流式咨询、情绪日记、知识库、数据分析、管理端，主流程是通的，属于"可演示的完整作品" |
| **能不能交付给真实用户（尤其心理场景）？** | **不能。** 存在**全站隐私越权**、**危机干预只展示不处置**、**密钥明文入库**三类致命问题 |
| **作为"接口自动化测试的被测系统"？** | **不成立。** README 声称测试框架在 `ai-api-test/`，但那里**只有 `venv/` 和一份 `redteam_full.txt`，测试代码一行都不存在** |

**一句话判断**：这是一个**功能闭环、工程质量停在课程作业/原型级**的项目。能跑、能演示、能答辩，但按"心理健康数据"的敏感级别，当前状态**不能给任何真人用**。

**最致命的三件事（必须最先做）**

1. **越权到了"裸奔"程度**：任何登录用户都能列出**全站所有人**的咨询会话、读取**别人**的私密对话原文、删除**别人**的会话、查看并删除**全站用户的心理日记**。（`PsychologicalChat.java:87-195`、`EmotionDiaryController.java:54-66`）
2. **危机干预是个空壳**：AI 会输出 `riskLevel`（0-3，3=危机），但**全项目没有任何处置逻辑**——不告警、不通知、不转介、不落库。对心理产品而言，这是"宣称有、实则无"的安全承诺。（`EmotionDiaryService.java:99`、`PromptManage.java:21-24`）
3. **密钥明文入库**：数据库口令、DeepSeek API Key、JWT secret 全部硬编码在 `application.yml` 里并随代码分发。（`application.yml:5,15,23`）

**改造建议**：分三期，**先止血、再重构、后升级**。P0 是一周内能做完的高收益加固，P1 是架构级重构，P2 才是对标同类项目的能力升级。

## 四、核心问题清单

按严重程度分六类。每条给「问题 → 证据 → 影响 → 改造动作」。

### 4.1 A 类：安全与隐私（P0，最高优先）

#### A1 越权读取全站咨询会话（最严重）

- **问题**：`GET /api/psychological-chat/sessions` **完全没有按用户过滤**，它查的是全表。
- **证据**：`PsychologicalChat.java:93-95`
  ```java
  consultationSessionMapper.selectPage(page,
      new LambdaQueryWrapper<ConsultationSession>()
          .orderByDesc(ConsultationSession::getStartedAt));   // ← 没有任何 eq(userId)
  ```
  返回体里还带了 `username` / `nickname` / `lastMessageContent`（`:112-124`）。
- **影响**：**任何注册用户登录后调一次这个接口，就能拿到全站所有人的咨询会话列表**，含用户名、昵称、最后一条消息预览 30 字。
- **改造**：拆成两个接口。用户端强制 `eq(ConsultationSession::getUserId, currentUserId)`；管理端独立路径 + `@PreAuthorize("hasRole('ADMIN')")`。

#### A2 越权读取 / 删除他人会话与消息

- **问题**：`deleteSession` / `sessionMessages` / `sessionEmotion` 三个接口拿了 `sessionId` 就直接查，**从不校验这个会话属不属于当前用户**。
- **证据**：`PsychologicalChat.java:139-149`（删除）、`154-178`（读消息）、`183-195`（读情绪）
- **影响**：遍历 `sessionId`（自增 Long，极易枚举）即可**读取所有人的私密心理咨询原文**，或**删掉别人的会话**。心理倾诉内容属于最敏感的个人数据，这条一旦泄露性质极严重。
- **改造**：抽一个 `assertSessionOwner(sessionId, currentUserId)`，在三个接口入口统一调用；查消息时用 `join` 或先查 session 判定归属。删除改逻辑删除。

#### A3 管理端接口零权限校验

- **问题**：`SecurityConfig` 只做了"白名单放行 + 其余需登录"，**没有任何角色校验**；`@EnableMethodSecurity` 是开着的，但全项目**没有一个 `@PreAuthorize`**。
- **证据**：`SecurityConfig.java:17`（开了方法级安全）、`:50-55`（只有 `anyRequest().authenticated()`）
  - `EmotionDiaryController.java:54-66`：`/admin/page` 可**分页读取全站用户的心理日记**、`/admin/{id}` 可**删除任意日记**
  - `KnowledgeArticleController.java:68-90`：普通用户可**创建/修改/删除文章、改状态**
  - `DataAnalyticsController.java:24`：普通用户可看**全站运营数据**
- **影响**：普通用户拿到管理员全部能力，且心理日记是"用户以为自己私密"的数据——这是**信任崩塌级**的问题。
- **改造**：所有 `/admin/**` 与写操作加 `@PreAuthorize("hasRole('ADMIN')")`；JWT 里放 `role` 并映射成 `GrantedAuthority`。

#### A4 密钥明文入库

- **证据**：`application.yml:3-5`（`root` / `已脱敏`）、`:15`（DeepSeek Key `sk-***已脱敏***`）、`:23`（JWT secret 硬编码）
- **影响**：随代码/压缩包分发即泄露，Key 可被盗刷（真金白银），库口令可直接拖库。
- **改造**：改 `${DB_PASSWORD}` / `${AI_API_KEY}` 环境变量注入；补 `.env.example`；**立即作废并重签那个 DeepSeek Key**（它已经外流到很多份拷贝里了）；加 `.gitignore`。

#### A5 文件上传无校验 + 静态目录公开

- **证据**：`SysFileInfoService.java:35-52`（只按扩展名判类型、无大小上限、`businessType` 直接参与拼路径，`:44-47` 可传 `../` 目录穿越）；`SecurityConfig.java:25`（`/files/**` 是 `permitAll`）
- **影响**：可上传任意类型/超大文件、可目录穿越、**上传的心理相关文件可被未授权枚举下载**；文件名是时间戳+随机数，可预测性尚可但不应依赖。
- **改造**：白名单扩展名 + MIME/魔数双校验 + 大小上限 + 文件名改 UUID + 路径 `normalize()` 后校验仍在根目录内 + `/files/**` 至少要求登录（敏感文件加签名 URL）。

#### A6 JWT 吊销与刷新缺失

- **证据**：`JwtConfig.java:14` 定义了 `refreshExpiration`（7 天）但**从未被使用**；`JwtTokenUtil.generateToken`（`:37-58`）只用 `expiration`；`User.java:48-51` 的 `logout()` **是空方法**。
- **影响**：24 小时内 token 无法吊销——用户改密码、被封禁、注销后，旧 token 依然有效。
- **改造**：短期 access token（15-30 分钟）+ refresh token；注销/改密写入黑名单（Redis）；过滤器校验黑名单。

#### A7 前端 XSS 风险（会放大成账号接管）

- **证据**：`MarkdownRenderer.vue:3` 用 `v-html` 渲染，`:26` 只转了 `<>`，`:48` 把未转义内容拼进 `href`；`articleDetail.vue:36` 直接渲染后端富文本；`consultation.vue:157` 用 `formatMessageContent` 后 `v-html`；而 token 存在 **localStorage**（`utils/request.js:14`）
- **影响**：`[x](javascript:alert(1))` 之类即可执行脚本；配合 localStorage token → **一次 XSS 等于账号接管**。
- **改造**：接 DOMPurify 清洗后再渲染；后端富文本入库前白名单过滤；中长期把 token 挪到 httpOnly Cookie + 加 CSP。

#### A8 敏感信息进日志 + 鉴权配置形同虚设

- **证据**：`JwtAuthticationFilter.java:42-52` 用 `System.out` 打印 URI 和**含 email/phone 的用户对象**；`UserService.java:53` 打印 token；`JwtTokenUtil.java:66` 从固定 header `token` 取值，**根本没读配置里的 `jwt.header` / `token-prefix`**（`application.yml:26-27`）
- **改造**：删掉所有 `System.out`，换 logback 并做脱敏；统一 `Authorization: Bearer`。

### 4.2 B 类：心理健康业务正确性（P0）

#### B1 危机干预"只有输出，没有处置"

- **证据**：`PromptManage.java:21-24` 只在系统提示词里写了"如果检测到自杀倾向，鼓励寻求专业帮助"；`EmotionDiaryService.java:99` 让模型输出 `riskLevel`；前端 `consultation.vue:253` / `emotional.vue:182` / `emotionDiary.vue:140` 三处都只是**把 riskLevel 映射成颜色**
- **全项目 grep 不到任何**：告警通知、工单、转介、人工介入、危机事件落库、紧急联系人
- **影响**：用户说"我不想活了"，系统回复一段温暖的话，然后**什么都没发生**。而产品对外呈现的是"有风险等级/危机预警"。这是**对用户的安全承诺造假**——比没有这个功能更糟。
- **改造**（三层，缺一不可）：
  1. **规则层**（不依赖大模型）：关键词/正则命中"自杀、不想活、遗书、了断"等 → 立即触发
  2. **模型层**：`riskLevel >= 2` 即升级
  3. **处置层**：独立 `crisis_event` 表落库 → 前端**强制**展示固定求助卡片（不可被 AI 回复顶掉）→ 管理端生成预警工单 + 通知值班人员 → 记录处置结果（合规要求）
  - 配套：UI 必须有醒目免责声明（"本系统不能替代专业诊疗"）

#### B2 情感计算体系与实现不一致

- **证据**：`课件.md` 定义"十级情绪"和 10 个 AI 可识别情绪枚举，但代码里没有对应的枚举/校验，全靠模型自由输出；`PromptManage.java` 也没有约束输出枚举
- **影响**：统计口径不可控，趋势图数据会漂移
- **改造**：情绪枚举落成 Java enum + 结构化输出强约束（`StructOutPut` 已有基础，应扩大使用）

### 4.3 C 类：数据一致性

#### C1 全项目零事务

- **证据**：全局搜不到一个 `@Transactional`
  - `PsychologicalChat.java:143-146`：先删消息再删会话，中间失败 → 消息没了会话还在
  - `EmotionDiaryService.java:60-73`：插入 → 调 AI → 再 update，AI 抛异常则留下半条脏数据
  - `PsychologicalSupportService.java:40-43`：建会话 + 写消息，非原子
  - `UserService.java:66-90`：查重 + 插入，并发下产生重复用户（虽有唯一索引兜底，但会抛难看的 500）
- **改造**：写操作加 `@Transactional`；AI 调用**移出事务**（避免长事务占连接），改成"先落库(NEW) → 事务外调 AI → 事务内回填结果"。

#### C2 N+1 查询 + 无上限分页

- **证据**：`PsychologicalChat.java:107-128` 对每条会话循环查"最后一条消息"和"消息总数"→ **1 + 2N 次查询**
- **改造**：一次 `in (sessionIds)` 批量查 + 内存聚合（或子查询/窗口函数）。

#### C3 死表与缺索引维护

- **证据**：`mental_health_assistant_full.sql` 里 `ai_analysis_task`（8 个索引）、`user_favorite` **有表无实体无 Mapper**，属于设计残留；索引整体是齐全的
- **改造**：确认用途后要么补实现、要么删表；引入 Flyway 管版本，别再手工导 SQL。

### 4.4 D 类：AI 工程能力

| 编号 | 问题 | 证据 | 改造 |
|---|---|---|---|
| D1 | SSE 反模式：在 `Flux.create` 里手动 `subscribe()`，断连不取消上游 | `PsychologicalSupportService.java:60-123` | 直接用 `chatClient.prompt().stream().content()` 返回 Flux，交给框架管生命周期 |

## 八、风险与注意事项

1. **修越权会改变接口契约**：`/sessions` 从"全站"变成"仅自己"，管理端页面会直接空掉——必须同步加管理端接口，否则改完后台就废了。**建议两边一起改、一起测。**
2. **危机干预是产品承诺，不是功能点**：如果 P0 的危机兜底做不完，**应当先把前端那些"风险等级/情绪预警"的展示撤掉或加显著免责说明**——给不出处置就不要展示预警，避免误导用户。
3. **AI 调用不要包进事务**：这是重构时最容易踩的坑，会把数据库连接池拖垮。
4. **Key 作废要有序**：先加环境变量支持 → 切新 Key → 再吊销旧 Key，避免服务中断。
5. **前端 `consultation.vue` 拆分要小步走**：40 KB 一锅端，建议先抽 composable（逻辑）再拆组件（视图），每步都能跑。
6. **本项目定位要明确**：如果它只是"课程作业 + 被测系统"，P0 做完即可收工；如果目标是真实上线，那必须做完整三期，尤其合规部分——**心理健康数据属于敏感个人信息，受《个人信息保护法》约束**。
